## 2. Keys and lines

- [x] 2.1 `key`: `Key::parse` takes `/`-separated segments and refuses, naming the rule, an empty key, a leading `/`, an empty segment, a `.` or `..` segment, a segment that is one of the layout's file names (`capture.rec`, `signals.rec`, `moves.rec`, `item.rec`, `brief.md`, `sends.rec`, held in one constant beside the roots, the refusal naming the segment and the file), and a first segment of `captures`, `moves` or `items`; `Key::segments` returns them in order. Tests cover every scenario of "A key names nothing in an inbox but its own capture" (adapter-contract), "A key that names a file of the layout is refused" among them. Proved by `devenv shell -- moon run capture:test`.
- [x] 2.2 `line`: `read_line(&str) -> Result<Line, Malformed>` reads a JSON object with exactly one of `capture`, `cursor` and `done`, ignoring other top-level keys; an offer needs `key` (checked by `Key::parse`), `source` and `event_at` (RFC 3339 with an offset, through `time`, kept as offered), and reads `title`, `url`, `raw` (relative paths with no `..` segment) and `excerpt` (every field, non-empty `text`, `kind` one of the five), ignoring other fields; a cursor is a string kept byte for byte; a completion holds `listed` and `failed` entries of `what` and `why`. Each refusal names the field, as `excerpt.text` or `done.failed[0].why`. Tests cover every scenario of "Every line is exactly one of three", "An offer carries a key, a source and an event time", "An own excerpt holds every field of a signal", "Raw material is named inside the raw place" and "A cursor is opaque and a completion counts the listing". Proved by `devenv shell -- moon run capture:test`.
- [x] 2.3 `line`: `Line::to_json` writes one line of JSON with no newline inside it, which `read_line` reads back equal; a test writes an offer whose excerpt text holds several lines, a cursor and a completion, and reads each back ("Lines are written as the host reads them"). Proved by `devenv shell -- moon run capture:test`.
