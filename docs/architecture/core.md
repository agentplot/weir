# weir rules

The rules that bind wherever a change is made in this repository,
written so a reviewer can point at a diff and say which rule it breaks.
The narrative is the statement in agentplot/blueprints,
`design/weir/requirements.md`; a rule here names the clause it
enforces and never restates it. There are no area pages yet; a rule
that binds only one crate moves to an area page when that crate
exists. Every rule below is drawn from the statement the user
ratified, or from a record the user accepted; none waits on a yes.
A rule that names a renamed thing names it as the user renamed it, in
their own words, which record 0003 carries. A kind's name and a
package's links follow the user's ruling of 2026-11-05, in their own
words, which record 0004 carries. A kind's landing fix follows the
user's decision of 2026-11-07, in their own words, which record 0005
carries. A delivery follows the user's direction of 2026-11-08, in
their own words, which record 0006 carries, and the statement's
clauses 100 to 113 and C.8 it was written into at blueprints 006fc34.

## Rules

### The crates and what they know

- **[core.1]** No crate keeps state, starts a process that outlives its call, or names a host, tool, machine or inbox: every function answers from its inputs alone, every write is one a caller asked for, and a child a crate runs for a write, git in the branch keeper, ends with the call.
- **[core.2]** Code outside the signals-folder import and the pack's cases names no tool of the family and no source.
- **[core.3]** No record weir defines holds a secret, and no code path writes one into a record, a line or a log.
- **[core.4]** No code path judges what a capture or a delivery's message says, chooses a move, cuts an excerpt except as the limit forces, lists a source, hands a delivery over or confirms one, starts an agent, submits or lands.

### The contract

- **[core.5]** An adapter's output is lines, each exactly one of an offer, a cursor or a completion; a line that is none or several, an import line among them, is refused as malformed, named with its reason, and stops no other line.
- **[core.6]** An offer is taken only with a key, a source and an event time, a key that names its own capture alone, and an own excerpt with every field present; a host reads of a line only the fields the contract names.
- **[core.7]** One event has one key on every machine and every run, and the key rule refuses a leading `/`, a segment empty, `.` or `..`, a segment that names a file the layout places, and `captures`, `moves` or `items` as a first segment.
- **[core.8]** An event time is the time at the source, never the time of listing or taking, and every age and weight reads it.
- **[core.9]** A cursor is opaque: no code path but its adapter's parses, compares or makes one, and a host hands back only the last cursor of a complete run.

### What a host writes

- **[core.10]** An inbox holds at most one capture per key: a held key writes nothing, banks nothing and is counted held, and no later offer under a key changes its capture.
- **[core.11]** Raw material is banked whole and unchanged on the machine that took it before its capture is written; a record holds a pointer `<hostname>:<path>` and never the material; nothing an adapter wrote that no taken capture names outlives the run.
- **[core.12]** The cut is one function: whole lines from the start to the last that fits together with the closing line, in C.1's one spelling, the closing line alone when none fits, nothing added when the text fits, a limit too short for the closing line alone refused, and the whole text banked whenever it is cut.
- **[core.13]** A capture and its own signal are written in one write; a capture with an own excerpt has exactly one signal and is never unread, and every other capture is unread when written.
- **[core.14]** Two hosts given the same lines write the same records, cut the same way: no host setting, clock, machine or random value reaches a record but the taken-at time, the machine's name and how the capture came in.
- **[core.15]** A run is recorded whole, what it took, held and refused with reasons, the completion's failures, the cursor kept and whether it was complete; a run without a completion or reporting failure advances no cursor and keeps every offer it made.

### Signals, moves and items

- **[core.16]** A signal's excerpt stands verbatim in its capture's raw material or is the own excerpt as cut, or the signal is refused; an imported signal alone is exempt.
- **[core.17]** A signal's identity is `<key>#<n>` in reading order; a capture has at most one reading, written whole or refused whole naming each signal not taken.
- **[core.18]** A signal has at most one standing move, a second is refused, only a replacement naming who replaced what changes it, and a move is one of the six with its consequence or is refused.
- **[core.19]** A batch is written whole or refused whole, and while it is proposed its moves do not stand; an unmoved signal is never deleted, however old.
- **[core.20]** An item's signals are read from standing moves and its weight is computed from them and never stored; an item's name is one its inbox has never had, nests under no other and holds no `/`; a host never writes a brief; a send keeps the brief as handed.

### Records and layout

- **[core.21]** A capture, a signal and a move never change once written; what changes is added beside them, and only `brief.md` is rewritten in place.
- **[core.22]** Every record names `format: weir-<record>/<major>`; a reader of a later major reads every earlier one, and no code path writes a record in a format it did not read.
- **[core.23]** Each capture lies at the one place its key fixes, with its signals beside it; moves, batches and items lie where no key reaches; an inbox is read whole from one tip, and a host keeps nothing of it the layout does not place.
- **[core.24]** Records are recutils at rest and JSON only in flight, and every file a write changes passes `recfix` and the records' checks before it lands.
- **[core.25]** An import is written from import lines by a host's import operation alone, never through take; it copies no raw material, banks nothing, writes no pointer of its own, checks no imported excerpt, keeps the key a capture was first held under and holds imported captures by key like any other; a reason or note the body gave with any move is kept as its note, a move of another word, or without its consequence, arrives unmoved, and crew's `new-territory` is a join into a proposed item named for its target.

### The shared branch

- **[core.26]** A write is formed against the tip its writer read, every check is made on the tip it lands on, and it lands only there; a refused push replays the write on the new tip, checks and all, up to the writer's bound, five unless set, then reports refused and never retries on its own.
- **[core.27]** A write is one commit through a temporary index touching no working copy, pushed never with force and with the tip read as the expected old value, and a branch with no remote moves by `update-ref` from that expected value.
- **[core.28]** A writers' lock keeps one machine's writers in turn, names its holder and its time, and never stands in for the check at the tip.
- **[core.29]** Every write's commit names what it did and who asked for it.

### Kinds

- **[core.30]** The kind format, its packages, their content hash and its locks are weir's, in `weir-kinds`, read through `read-kinds`, `read-package` and `read-lock` alone, and a lock spelled by `weir-kinds` alone; a reader returns a section it does not know unread and unrefused, fails on none, and changes no declaration, package or lock.
- **[core.31]** A declaration is checked whole and refused naming the field: no stage on a kind that does not land, `stages` left out of a kind's table that declares a kind, a stage with no name or prompt, two stages of one kind sharing a name, an `on_fail` naming no stage of its kind, a `landing_fix` or `max_landing_fixes` on a kind with stages, a `landing_fix` that is no identity with its version, a field of the wrong shape, a deliverable not of the seven spellings, a `repeat` other than `per-task-group` or on a stage whose deliverable is not `tasks`; `stages = []` on a kind that lands reads as a kind with no stages, which may name in `landing_fix` its landing fix, an identity with its version returned as written, and in `max_landing_fixes` how many it runs; a version left out reads as 1, and a `quiet`, `on_fail`, `max_send_backs`, `landing_fix`, `max_landing_fixes` or elaboration's `ending` left out is returned left out.
- **[core.32]** No code path in weir resolves a kind's name among a tool's, a repository's, a launch's and the packages a reader holds, chooses which locks are read or which version a name takes, joins settings given to a kind declared elsewhere to that kind's own, checks an agent's settings, its mode among them, or says how a repetition is worked or standing instructions sent: each is the reader's rule.
- **[core.41]** A kind's `agents` table and each `agents.stages.<stage>` table are returned as written with the kind; a `[kinds.<kind>]` table holding `agents` and nothing else the format names declares no kind, is returned apart from the kinds as settings given to that name, and is never refused as a kind with no stage.
- **[core.42]** A kind's identity is its source, its name and its version, written `<source>/<name>@<version>`, the source and the name each one or more ASCII letters, digits, `_` and `-`, and the version a whole number of at least 1 with no leading zero; `read-kinds` refuses a kind's table or a table of settings under any other key, naming it; a declaration holds one version of each name it declares; a tool's own source is the tool's name as its reader gives it, a repository's `repo` and a launch's `launch`, and no source from outside takes one of these.
- **[core.43]** A package is a directory whose `kind.toml` at its root declares exactly one kind, with every part it names a regular file inside it; one that declares no kind or several, gives settings to a kind it does not declare, or names a part by a `..` segment or an absolute path, or a part it does not hold, is refused naming the field, one that holds a symbolic link is refused naming the link's file, and one held under an identity whose name or version is not its declaration's is refused naming both.
- **[core.44]** A package's content hash is one function, C.4's, over every regular file of the package with its path relative to the root, so where the package lies and when its parts were written reach no hash.
- **[core.45]** A lock of kinds records each identity at most once with its content hash, or is refused naming the field; reading one changes nothing; and a kind whose package's content hash is not the hash its lock records is refused naming the kind and both hashes.

### Cadence

- **[core.33]** Cadence reads a schedule, the last run and now and nothing else, in the machine's local time, and a run missed while the machine slept is caught up once.

### Adapters and the pack

- **[core.34]** The folder drop and the meeting file, the two built-in adapters, speak the contract through the same lines as any adapter and are run the same way, and their keys are by the sha256 of the file; the signals-folder import is no adapter (core.25).
- **[core.35]** Every case of the pack is one folder under its shape, one of C.7's seven, and cites the clauses it exercises, and a case of the branch, inbox, kinds, cadence or delivery shape runs against weir's own crate in its tests; the pack's check fails when a cited number names no clause or a clause of A.1 to A.10, A.14 or 71 is cited by no case, and counts neither 65, 67 and 68, which the check's own tests prove, nor 69 and 70, which core.1 and core.4 hold; the pack runs with no network, no source and fixed inputs.
- **[core.46]** `weir conform` holds a host through the one seam C.7 fixes: for each case a bare repository with no remote, its branch `inbox` seeded with the case's starting records, the host run with the intake's, a run's or the import's flags, and the last object it prints, `weir-report/1`, read with the records at the branch's tip; a refusal is compared by its line, its key and the phrase the case names in its reason, and records as written.
- **[core.36]** Every profile, host and adapter passes the pack, one that fails it is not one, and a profile adds nothing to Parts A and B.

### Deliveries

- **[core.47]** A delivery is recorded once per key, with its message and its readers, and never changes: recording under a held key returns the delivery that stands and adds nothing, and a delivery with no key, no message or no reader, or naming a reader twice, is refused naming the field.
- **[core.48]** A delivery stops being owed to a reader on that reader's confirmation naming its key and on nothing else: a hand-over confirms only where its call says the reader confirms on receipt, and then both are returned together; a confirmation of a key the records hold no delivery under, or by a reader the delivery does not name, is refused naming which; a second confirmation adds nothing and says when the first was.
- **[core.49]** A delivery's expiry is fixed when it is recorded, from the span its caller gives; an expired delivery is returned with its reader by every answer of what is owed until that reader confirms it, and no call drops, hides or ends one.
- **[core.50]** Every answer of what a reader is owed says whether its name is known, read from a `weir-known/1` record alone, which the confirmation that first confirms under the name returns.
- **[core.51]** The delivery calls are functions over the records and the times their caller passes: none reads a clock, holds or reads a store, hands a message over or reads a message's words, and each returns the records to add, never writing them.
- **[core.52]** A delivery's records are the four of C.8, spelled in recutils and in JSON by `weir-delivery` alone and each read back as written; a deliverer's store is held to the pack through its read and add alone, and weir holds no store but the ones its tests make.

### Design and records

- **[core.37]** A change that bears on a clause cites the clause by number; a clause that no longer holds is changed in the statement first, never worked around here.
- **[core.38]** Nothing commercial, no pricing, tier or customer, appears in this repository.

### The gate

- **[core.39]** Every file the tree tracks is owned by a formatter the gate runs, or is excluded by name with its reason; every language with a linter is linted; every crate is a moon project of its own, listed in `.moon/workspace.yml` with its language, whose check-fast tasks format, lint and test it, one task per check.
- **[core.40]** Every tool a gate task runs is the version the tree pins, on every host that runs the gate.
